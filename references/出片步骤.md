# 换文案出片步骤

> **如果是按口播配音出片**（时间跟着配音走、任意时长、支持 **16:9 横屏（1920×1080）与 3:4 竖屏主标准（1080×1440，兼顾 9:16 兼容）**、三脚架零晃动动效、音乐自动循环压低、支持无 `.mp4` 内置卡片出片），请直接使用模块化口播版文档：
> - 总入口与 `from_audio.py` 快速起片：[../SKILL.md](../SKILL.md)
> - 蓝光口播版 `BlueTalk` / `BlueTalk3x4`（兼容 `BlueTalkPortrait`）：[blue-talk.md](blue-talk.md)
> - 虹彩对话版 `PrismTalk` / `PrismTalk3x4`（兼容 `PrismTalkPortrait`）：[prism-talk.md](prism-talk.md)
> - 纸感排印版 `PaperTalk` / `PaperTalk3x4`（兼容 `PaperTalkPortrait`）：[paper-talk.md](paper-talk.md)
> - 纯白镜头版 `CleanTalk` / `CleanTalk3x4`（兼容 `CleanTalkPortrait`）：[clean-talk.md](clean-talk.md)

以下内容仅适用于早期的**四套固定配乐节拍横屏宣传短片**（它们的时间轴跟着各自的固定配乐走）。

只换文案和素材时照这一页做，不需要改任何 `.tsx` / `.ts` 代码。
如果要改的东西配置里没有（加段落、改时间、改镜头、改版式），停下来，这不是换文案，要单独设计。

所有命令在 `template/` 目录下运行，一次只跑一条，渲染不要并行。

## 每套改哪个文件

| 风格 | 片名 | 配置文件 | 入口 | 配乐 |
| --- | --- | --- | --- | --- |
| 蓝光展廊实片版 | `BlueGalleryLive` | `public/blue-gallery/live.json` | `src/blue-gallery-preview.tsx` | 固定，不用重做 |
| 虹彩对话版 | `PrismChat` | `public/prism-promo/chat.json` | `src/prism-preview.tsx` | 改完跑 `python3 scripts/prism-chat-music.py` |
| 纯白镜头版 | `CleanUiLive` | `public/clean-ui-workflow/live.json` | `src/index.tsx` | 固定，不用重做 |
| 纸感排印 | `PaperLine` | `public/paper-line/line.json` | `src/index.tsx` | 改完跑 `python3 scripts/paper-line-music.py` |

各配置字段的含义见同目录的 `blue-gallery-demo.md`、`prism-product-demo.md`、`clean-ui-demo.md`、`paper-line.md`。

## 步骤

1. 改配置文件。只改文字和素材，不增减字段，不改数组里的项数（除非该风格的说明写了可以）。
2. `npm test`。报错信息会直接说哪一句超长、哪个素材不够长、哪里出现了平台名。按提示改配置，直到全部通过。
3. `npm run typecheck`。
4. 需要重做配乐的风格，跑上表的配乐脚本。
5. 抽帧：`npx tsx scripts/check-<风格>.ts`（`check-blue-live` / `check-prism-chat` / `check-clean-live` / `check-paper-line`），图在 `out/<风格>-previews/`。逐张看，见下面的停止条件。
6. 导出。
   - 入口是 `src/index.tsx` 的：`npm run export -- <片名>`，成片在 `exports/`。
   - 另外两套：`npx remotion render <入口> <片名> exports/<片名>.mp4 --codec=h264 --crf=18 --concurrency=2 --browser-executable="$(node -e "console.log(require('./scripts/browser-path.cjs').browserExecutable()||'')")" --log=error`
7. 解码检查：`ffmpeg -v error -i <成片> -f null -`，没有任何输出才算通过。
8. 运动量：`python3 scripts/check-motion.py <成片>`，和下表的基准比。只要有一秒低于 1.0 这条命令就会以失败状态退出，这不代表出错，以下表为准。

## 停止条件

出现下面任何一条就停下来报告，不要自己改代码绕过去：

- 测试或类型检查不通过，而且按报错改配置也解决不了。
- 抽帧里有：文字出框或被截断、两个元素压在一起、整张画面空白或只有底色、文字显示成方块。
- 解码检查有输出。
- 运动量平均值比基准低两成以上，或者低于 1.0 的秒数比基准多。

| 风格 | 平均运动量基准 | 本来就低于 1.0 的秒 |
| --- | --- | --- |
| 蓝光展廊实片版 | 6.95 | 第 29 秒（收尾停留） |
| 虹彩对话版 | 6.13 | 以上一次成片为准 |
| 纯白镜头版 | 2.96 | 以上一次成片为准 |
| 纸感排印 | 6.20 | 第 0 到 2、22、27、30 到 31 秒 |

## 一直要守的规则

- 文案和画面里不出现平台名、仓库地址、链接；评论口令后面不写「发给你」。
- 素材目录（各风格 `public/.../media/`）不进版本库，换电脑先从 `成片/` 复制过来；片源要是 60fps。
- 纸感排印用到系统自带的宋体和楷体，换电脑先确认有。
- 不新增依赖，不推送；提交信息用 Conventional Commits。
- 做完把成片复制到 `成片/<风格>-<日期>/`，在 `LOCAL_STATUS.md` 追加一条记录。
